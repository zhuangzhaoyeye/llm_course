# 课程内容生成

## 描述

把「设计理念」变成可交付的卡片 HTML。产出必须是**能被学员自己推一遍**的卡片，不是知识罗列。

## 使用场景

触发：新增一节课 / 新增或改写某张卡片 / 补追问 / 加计算走查 / 调整问题与提示。

不触发：只想构建产物（用 `course-build`）、只想验证（用 `course-verify`）、只想评审既有内容（用 `card-review`）。

## 指令

### 第 0 步 定位课程

1. 读 `src/lessons/manifest.json` 确认课号映射（**id 是引擎内部 id，不等于学员看到的课号，写错 = QnA 贴错卡片**）。
2. 读 `src/lessons/lesson-<id>.html` 了解已有卡片的问题序列与风格。
3. 任何涉及「某篇论文 / 某模型做了什么」的表述，先 WebSearch 查证再落笔，禁止凭记忆。

### 第 1 步 设计推理链（先纸面，后代码）

新一课按因果链排问题序列，不允许按知识分类排：

```
为什么需要 → 怎么算 → 有什么坑 → 分岔路 → 怎么组合 → 怎么用
```

每张卡的问题必须能**被上一张卡的结论逼出来**，且不预设结论（问号结尾）。

### 第 2 步 写卡片的五个阶段

| 阶段 | 落点 | 硬要求 |
|---|---|---|
| 激活 | `.card-q-text` + `.card-q-hint` | 问题以问号结尾、不预设结论；提示给方向不给答案 |
| 锚定 | `.card-bg` | 提出者 + 年份 + 当时要解决的痛点 |
| 推导 | `.calc-block` | **最小真实句子 + 具体数字**，每步独立 `.step-title`，数字从前一步自然导出，无魔法常数 |
| 升华 | `.highlight-box` | 有 X → 结果 A；没有 X → 结果 B。让学员看到代价 |
| 追问 | `allHardcodedQnA[id][cardId]` | 每条答案带 `<table>` 和数字 |

**每个新机制/术语必须配 1 个可复用的生活类比**（≤2 句），且术语首次出现必须紧跟白话定义。见 `20-content-rules.md` 第六节。

### 第 3 步 写文件

- 卡片 HTML 追加/修改在 `src/lessons/lesson-<id>.html`
- 追问数据改 `src/shell.html` 里的 `const allHardcodedQnA`
- 卡片主题改 `src/shell.html` 里的 `cardTopics` / `allCardTopics`
- 组件骨架照抄 `references/card-template.html`，不要自创结构
- **覆盖地图写进 `docs/coverage-maps.md`（不进学生页面）**：新课在此补一节，四段固定（本领域标准知识块 / 本课覆盖 / 其余去向 / 有意不讲），并在 `tools/coverage_check.js` 的 `ANCHORS` 登记该课锚点。它是备课自查与跨课连贯性的保障，**但不放进 `lesson-<id>.html`**——学生看到一个"地图"会很奇怪（2026-10-04 用户要求）。

### 第 4 步 逐条核验（**不可抽样、不可跳过、不省 token**）

对本轮涉及的**每一个条目**逐一核验。**范围 = 每张主问题 + 该主问题下挂的每一条追问**，一条不漏。

**每条断言先归类，再交给对应裁判**（不许什么都塞给 python）：

| 类型 | 唯一裁判 | 核验方式列必须匹配 | 来源列必须给 | 置信度 |
|---|---|---|---|---|
| `算术` | 脚本复算 | `python` / `重算` / `复算` | 可复算的算式 | 可保证 |
| `事实` | 联网 + 一手来源 | `web` / `搜索` / `一手` / `论文` | 链接，或写明「未找到/无来源/待人工」 | 可保证 |
| `推导` | 反例 + 边界检验 | `推导` / `反例` / `边界` / `量纲` / `极限` | **边界条件或反例** | 需标注 |
| `经验` | 无 —— 只能标注 | `来源` / `web` / `估算` / `标注` | 链接，或显式标「估算/示意」（**无来源不得判 PASS**） | 估算 |
| `语义` | 只有人 | `语义` / `人判` / `对照` | 所依据的规则条款 | 需标注 |

产出**逐条核验报告**到 `reports/<lesson-id>-逐条核验.md`，**8 列固定顺序**（缺列、条数不足或类型/方式不匹配 = 视为未核验）：

```
| # | 定位 | 待核验断言 | 类型 | 核验方式 | 来源/算式 | 置信度 | 判定 |
|---|------|-----------|------|---------|----------|--------|------|
| 1 | Card 2 主问题 | Q×K^T = 0.38 | 算术 | python 重算 | 0.6×0.4+0.2×0.7=0.38 | 可保证 | PASS |
| 2 | Card 3 追问 2 | Transformer 2017 年发表 | 事实 | WebSearch 一手核验 | https://arxiv.org/abs/1706.03762 | 可保证 | PASS |
| 3 | Card 5 追问 3 | 去掉 W_O 质量下降 5-10% | 经验 | 来源核查 | 未找到一手来源，标注估算 | 估算 | WARN 需标「估算」 |
```

**判定为 ERROR 的必须当场修复**，不允许"先记下来后面再说"。报告还必须满足 **H4 锚点覆盖**：每张卡的可核验锚点数（`.card-q-text` / `.card-bg` / 每个 `.content-section` / 每个 `.calc-block` / 每个 `.highlight-box`·`.analogy-block`·`.compare-table`）都要有对应行，少一条 `review_check.js` 直接 FAIL。

### 第 5 步 交付（**生成完成必须串联质检，不可只跑构建**）

```
node tools/review_check.js --lesson <id>   # 校验逐条核验报告覆盖度（零依赖）
node tools/coverage_check.js               # 覆盖地图归档/锚点/学生页面无残留（新课必过）
node tools/content_verify.js --src         # 内容层门禁
python3 scripts/build.py                   # 构建
node tools/content_verify.js               # 产物层门禁
node tools/verify.js                       # 渲染层（装了 Playwright 时）
```

然后再**调用 `card-review` skill 对新增内容做一次独立质检**——生成者不能只用自己的标准验收自己的产出。两步都过才算完成。

任一 FAIL 都不算完成；`review_check.js` 报覆盖不全 = 等于没做逐条核验。

### 第 6 步 反哺规则

本轮踩到的坑，按 `30-dev-rules.md` 第五节「Bug → Check」追问「下次怎么自动拦住它？」，能进脚本的当场进脚本。

## 示例

用户说「加一卡讲 KV Cache 为什么必要」：

1. 查 manifest 定位课 id；读该课现有卡片，找到它承接的问题。
2. 设计问题：「每生成一个 token 都要重算前面所有 token 的 K 和 V，多浪费？」→ 提示：「只算一次和每次都算，差多少？」
3. 计算走查：用具体序列长度和 d_model 算出重复计算量倍数，每步一个 step-title。
4. 升华：有 KV Cache → 显存换时间；没有 → attention 成本随长度平方增长。
5. 补 5 条追问，每条带 table 与数字；每条追问逐条联网核验。
6. 写逐条核验报告 → `review_check.js` → 构建 → 两个门禁 → 调 `card-review` 独立质检。
