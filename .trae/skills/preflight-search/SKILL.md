# 每轮强制联网搜索（Preflight Search）

## 描述

本项目的**第一优先前置动作**：每轮对话**先搜再答**，即使判断"没必要"也必须搜。目的不是形式合规，而是让每个结论都有**可核验的外部依据**，而不是靠模型的预训练记忆。

> 全局 `~/.trae-cn/skills/web-search/SKILL.md` 是「按需」语义（非强制）；本 skill 是「**每轮强制**」语义，两者不冲突，以本 skill 为准。

## 使用场景

**每轮对话都触发**，无例外。包括：写课程内容、改代码、评审、讨论、甚至"帮我改个错别字"。

唯一允许跳过的情形：**工具层面搜索失败**（网络不可用 / 接口报错）——此时必须声明"本轮搜索失败，以下基于预训练知识，需人工核实"，不得静默跳过。

## 指令

### 第 1 步 提炼本轮核心目的（关键环节，不可省）

不要拿用户的原话去搜，先回答三件事：

1. **本轮要解决的问题是什么**？（一句话，剥掉指令外壳）
2. **属于哪一类**？（见下表）
3. **有哪些说法需要外部核验**？（尤其是数字、论文归属、版本、政策、当前最佳实践）

| 类型 | 特征 | 搜索要拿到什么 |
|---|---|---|
| **查证型** | 涉及论文做了什么、某数字/事实是否正确 | 一手来源（论文 / 官方文档）的原文表述 |
| **前沿型** | 问业界现状、最佳实践、竞品 | 近 12 个月内的实践与对比，带年份 |
| **决策型** | 要在多个方案里选一个 | 各方案的失败案例与边界条件，而非优点罗列 |
| **操作型** | 写代码 / 改结构 / 配环境 | 官方文档与已知坑（版本相关） |
| **元讨论型** | 讨论流程、规则、方法论 | 该方法论在业界的成熟做法与反例 |

### 第 2 步 构造 query（2–4 条并行，中英文各至少一条）

原则：**分解、具体化、带年份、多 variant**。

```
# 查证（一手来源优先）
"{主张} original paper {year}"  /  "{论文名} {具体论断}"

# 前沿
"{topic} {year} best practice comparison"

# 决策
"{方案A} vs {方案B} production failure cases {year}"

# 操作
"{库/框架} {版本} {具体行为} official docs"

# 元讨论 / 兜底（"感觉没必要搜"时用这条）
"{本轮话题} {year} common pitfalls lessons learned"
```

> **兜底原则**：判定"没必要搜"时，必须至少用兜底模板搜一条。搜到的东西可能确实不相关，但**"搜了没用"可以记，跳过不搜不行**。

### 第 3 步 执行

- 首选内置 `WebSearch`（`num` 取 5–8），2–4 条并行
- 需要正文细节时用 `WebFetch` 抓 2–4 个最高质量来源
- 抓取优先级：**官方文档 / 论文 > 官方博客 > 技术博客 > 论坛聚合**

### 第 4 步 来源分级与采纳判定

| 等级 | 来源 | 用法 |
|---|---|---|
| A | 论文原文、官方文档、标准规范 | 可直接采纳为事实 |
| B | 官方博客、知名工程团队实践 | 可采纳，标注来源 |
| C | 技术博客、教程、聚合站 | 仅作参考，与 A/B 冲突时以 A/B 为准 |
| D | 论坛、问答、无署名内容 | 只用来说明"存在这种说法"，不作为依据 |

**采纳前必须自问**：这条来源**真的包含**我要说的那个论断吗？还是只是主题相近？（"引用 ≠ 来源支持论断"）

### 第 5 步 综合作答

1. 明确区分**来自搜索的事实**与**自己的推断**
2. 多源冲突 → 列出不同说法 + 给出倾向判断 + 说明依据等级
3. 标注信息时间点（尤其版本、政策、价格）
4. 搜索无法支撑的结论 → 标注「基于预训练知识，未经外部核实」

### 第 6 步 输出契约（每轮回复末尾必须附）

```
---
[联网自检] 已联网：是｜搜索轮次：2｜query：q1 / q2｜采纳：S1, S2｜未采纳但有影响：S3（原因）
[来源]
- [S1] A级 标题 — URL（支撑：xxx 论断）
- [S2] B级 标题 — URL（仅参考，未采纳：与 S1 冲突且等级较低）
```

**自检字段必须诚实**：搜索失败就写"否 + 原因"，不要为了合规谎报。

## 能保障什么、不能保障什么（必须向用户说清）

**能显著改善**：时效性与前沿性（预训练知识必然有截止日期）、可核验性（有出处才能被质疑和复查）、避免把"记忆里的说法"当成事实（如把 Sinusoidal 说成"标签表"）。

**不能保障**：

1. **引用 ≠ 正确**。来源必须真的包含该论断，这需要**语义核验**，工具判不了。
2. **检索质量决定结论质量**。检索返回了错误文档，模型会**自信地引用它**。
3. **置信度与准确率不相关**，不能靠"模型很有把握"来过滤。
4. **数字类仍然需要人工金标**——与本项目 `20-content-rules.md` 的置信度分级一致：算术可复算、逻辑链需标注、经验数字不可自证。

> 因此本 skill 是**必要条件，不是充分条件**。正确性的最后一道关永远是人工金标。

## 降级策略

| 情况 | 处理 |
|---|---|
| 搜索结果为空 | 换措辞 / 去时间限制 / 换语言 / 缩短到核心词 |
| 抓取失败或需登录 | 跳过，换替代源；不要反复重试同一 URL |
| WebSearch 报错 | 明示"本轮搜索失败，以下基于预训练知识，需人工核实" |
| 全部来源都是 D 级 | 只作"存在这种说法"的陈述，不作为依据，并标注需人工核实 |
