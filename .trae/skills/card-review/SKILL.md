# 卡片评审（质检）

## 描述

对既有卡片做内容质量评审。**逐条进行，不抽样、不省 token**，产出「定位 + 问题 + 严重度 + 改法」的可追溯清单 + 带来源的核验证据。

> **触发词**：用户说「检查」「自检」「质检」「体检」「评审」→ 就是本 skill。
> 其中「跑验证脚本」属 `course-verify`；本 skill 管的是**内容语义与正确性**。

## 使用场景

触发：检查某课 / 某几张卡片、自检、体检现有课程、判断卡片是否达标、排查"哪张卡不行"。

不触发：写新卡片（用 `course-content`）、只跑脚本（用 `course-verify`）。

## 指令

### 第 0 步 先跑机械检查，别用眼睛替代脚本

```
node tools/content_verify.js --src --quiet
```

脚本能判的（组件缺失、div 平衡、绑定一致性、追问条数、数字门禁）**直接采信脚本结果**，人只判脚本判不了的语义问题。

### 第 1 步 划定逐条范围（**一条不漏**）

```
逐条范围 = Σ 每张卡 (1 个主问题 + 该主问题下挂的每一条追问)
```

先把范围列清楚（第几课、几张卡、共几条），再开始逐条过。**抽样 = 违规**。

### 第 2 步 逐条核验（六个原子步骤，每条都要走）

| # | 步骤 | 怎么做 | 不可跳过的原因 |
|---|------|--------|--------------|
| 1 | 问题是否可思考 | 读 `.card-q-text` 原文 | 自动检测判不了"是否预设结论" |
| 2 | 提示是否泄题 | 读 `.card-q-hint` 原文 | 提示给答案 = 废掉思考环节 |
| 3 | 先验与类比是否补齐 | 读正文首段与 `.card-bg` | 缺先验 = 学员跟不上；缺类比 = 学不进去 |
| 4 | **数字独立重算** | 对每个 `.calc-block` 与**每条追问答案**用 `python3 -c` 重算 | 纯文本推理会自我欺骗（历史把 softmax 0.40/0.60 写成 0.25/0.75） |
| 5 | **逐条联网核验** | 每条事实/论文/版本/经验数字断言，逐条 WebSearch | 经验数字最可能是幻觉 |
| 6 | 桥接是否自然 | 语义判断，对照前一卡结论 | 硬塞推荐类比反而干扰理解 |

### 第 3 步 三大验证维度（必答，不能只答一项）

> 完整判据见 `20-content-rules.md` 第八节。名词一律按 `15-naming.md`。

| 维度 | 答什么 |
|---|---|
| **1 推理链**（`.roadmap`） | 是否符合第一性原理（起点是**任务约束**还是"旧方案不行"）、每步连接词是否可检验、能否**空白纸重建**、有无**正交维度插入** |
| **2 形式** | **主卡片**（`.card`）五阶段是否齐备 + 有类比/术语定义/桥接；**追问卡片**（`.qna-item`）问句是否真会被问、答案是否带 table+数字、`.qna-title` 声明条数是否与实际一致 |
| **3 正确性** | 算术逐条 `python3 -c` 重算；事实逐条 WebSearch 并记 URL；经验数字标「估算」；同课基础量口径是否一致 |

结论必须按固定措辞给（禁止写"整体没问题"）：

```
维度1 推理链：符合 / 部分符合（第 N 步正交插入）/ 不符合 —— 证据：…
维度2 形式：主卡片 N 张合格、M 张不合格（定位…）；追问卡片 N 条合格、M 条不合格（定位…）
维度3 正确性：数字 x/y 已重算一致；事实 x/y 已联网核验（x 条标注需人工核实）
```

### 第 4 步 类型路由与置信度（**每条断言先归类，再交给对应裁判**）

不许"什么都塞给 python"：一条断言该由谁裁决，取决于它的类型。下表是唯一口径，`review_check.js` 会机械校验（H1a/H1b/H1c/H2/H3）。

| 类型 | 唯一裁判 | 核验方式列必须匹配 | 来源列必须给 | 置信度 | 失效模式（必须防） |
|------|---------|------------------|-------------|--------|------------------|
| `算术` | 脚本复算 | `python` / `重算` / `复算` | 可复算的算式 | 可保证 | 脚本只判"我让它判的"；口径没写清就无从判 |
| `事实` | 联网 + 一手来源 | `web` / `搜索` / `一手` / `论文` | 链接，或写明「未找到/无来源/待人工」 | 可保证 | **引用 ≠ 支持**（引主题相近的博客当依据） |
| `推导` | 反例搜索 + 边界检验 | `推导` / `反例` / `边界` / `量纲` / `极限` | **边界条件或反例** | 需标注 | 缺反例只是"讲得通"，不是"对" |
| `经验` | 无 —— 只能标注 | `来源` / `web` / `估算` / `标注` | 链接，或显式标「估算/示意」 | 估算 | 把估算当已证实；**无来源者不得判 PASS** |
| `语义` | 只有人 | `语义` / `人判` / `对照` | 所依据的规则条款 | 需标注 | 假装工具能判（预设结论/泄题/类比恰当） |

> 经验数字举例：PPL 变化、推理快慢倍数、"某些头冗余"的比例——**没有一手来源就只能标「估算」**，不许写成"实践证明"。

### 第 5 步 产出核验报告（**可复现的关键**）

写到 `reports/<lesson-id>-逐条核验.md`，逐条一行，**8 列固定顺序**（缺列、条数不足或类型/方式不匹配 = 视为未核验）：

```
| # | 定位 | 待核验断言 | 类型 | 核验方式 | 来源/算式 | 置信度 | 判定 |
|---|------|-----------|------|---------|----------|--------|------|
| 1 | Card 2 主问题 | Q×K^T = 0.38 | 算术 | python 重算 | 0.6×0.4+0.2×0.7=0.38 | 可保证 | PASS |
| 2 | Card 3 追问 2 | Transformer 2017 年发表 | 事实 | WebSearch 一手核验 | https://arxiv.org/abs/1706.03762 | 可保证 | PASS |
| 3 | Card 3 主问题 | softmax(0.2,0.6)=0.25/0.75 | 算术 | python 重算 | 实为 0.4013/0.5987 | 可保证 | ERROR 数值错 |
| 4 | Card 1 追问 1 | LSTM 500 词后残余 ~0.3 | 经验 | 来源核查 | 未找到一手来源，标注估算 | 估算 | WARN 需标「估算」 |
```

校验：`node tools/review_check.js --lesson <id>`（覆盖度 + **锚点覆盖 H4** + 类型路由 H1~H3 + 枚举 + ERROR 清零）

### 第 6 步 对抗式复查（**台账全绿 ≠ 找全**）

第 5 步过完、门禁全绿之后，必须再走一遍**专找漏项**的复查。原因：门禁原先只能管「已列出的行」，**管不了「有没有漏列」**——一条错误断言如果从没被写成一行，门禁 100% 看不见它。

**已机械化（H4 锚点覆盖，由 `review_check.js` 强制）**：

- 每张卡的可核验锚点数 = `.card-q-text` 1 + `.card-bg` 1 + 每个 `.content-section` 1 + 每个 `.calc-block` 1 + 每个 `.highlight-box` / `.analogy-block` / `.compare-table` 1；
- 报告里**以「Card N」定位的行数必须 ≥ 该卡锚点数**，少一条即 FAIL 并报出是哪张卡（`Card 4 0/7` 这样的格式）。
- 效果：少列一条断言 = 行数不足 = 过不了门禁，**逼着把每个锚点走完，而不是凭人挑重点**。

**仍需人做（门禁判不了）**：

1. **同源扫描**：已判定为 ERROR 的每个错误，回到全文找它是否在别处**重复出现**（实测：E5/BGE 归属错误在同一课出现两处，第 1 轮只抓了一处 —— 这是 H4 也拦不住的，因为两处都有行，只是**只给一处判了 ERROR**）。
2. **逐句扫数字**：正文里每个含数字的句子是否都有行、是否标了「示意」。

> 实测代价：第 1 课第 1 轮列出 5 条 ERROR，第 2 轮对抗式复查又补出 2 条（其中 1 条是 P0）。**H4 只解决「列不列」，「列得对不对」仍靠人。**

### 第 7 步 输出问题清单

按严重度排序，每条给三件套：**定位 → 问题 → 改法**。

| 定位 | 问题 | 严重度 | 改法 |
|---|---|---|---|
| 第1课 Card 3 | Softmax 与输入对不上（0.25/0.75 应为 0.40/0.60） | **P0** | 按 python 重算值改正，或标「示意」 |
| 第1课 Card 5 | d_model 口径不一致（bg 512 vs calc 768） | P1 | 统一口径或注明来源 |
| 第1课 Card 3/4 | 提示泄题、问题预设结论 | P1 | 改为中性提问，提示只给方向 |

严重度：P0 = 事实/计算错误或违反门禁；P1 = 违反设计理念（无类比、无桥接、泄题）；P2 = 表达与流畅度。

### 第 8 步 独立盲审 × 差集比对（**解决"伪第三方"**）

前 7 步的"质检"是**同一个模型、同一个上下文**在做——LLM-as-judge 的自偏好偏差有实测：在生成者本来答错的条目上，评审方把"自己产的"判为合格的概率**高出 50% 以上**（arXiv:2604.06996）。所以必须补一次**信息独立**的评审：

1. **盲审**：起一个独立 subagent，**只给**卡片原文 + 追问数据 + `20-content-rules.md` + `10-course-design.md`；
   **明确禁止**它读 `reports/`（含我方结论）与 `30-dev-rules.md`（含我方基线）。
   产出 `reports/<id>-盲审.md`：一条一行的缺陷表 + 「无法判定」清单。
2. **差集比对**：把盲审清单与我方台账做差集，写进核验报告：
   - **交集** = 双方独立命中（可信度最高）
   - **盲审独有** = **我方漏检**（这是唯一的可量化质检指标：漏检率 = 盲审独有 / 盲审总数）
   - **我方独有** = 盲审漏检
3. **强制补账**：盲审独有的每一条都必须补进台账并给出类型/来源/判定/处置。

> 必须诚实说清：盲审只能消除"看过我的结论"这条**信息依赖**，**消除不了同族模型的自偏好偏差**。第 1 课实测：我方漏检率 **29%**（盲审 31 条里漏 9 条，含 1 条我曾判 PASS 的 P0 —— 且我第一次统计时把漏检率算成了 27%，**连统计本身都会错**），盲审也漏了 9 条。**没有全知验证者。**
>
> **本步骤已由门禁强制**（`review_check.js` A 组），不做就会 FAIL：
> - **A1** `reports/<id>-盲审.md` 必须存在；
> - **A2** 盲审报告必须含 ≥5 行缺陷表，且至少 1 行带 http 链接（证明盲审方确实联网核验过）；
> - **A3** 核验报告必须含「差集」段与**显式漏检率数字**（"我记得大概是…"不算数）。

### 第 9 步 债务闭环（由 `review_check.js` 强制）

台账第 9 列「处置」必填枚举：`已修` / `待修` / `不改`（不改须带理由）。判定为 WARN / ERROR 的行必须填。
**目的**：ERROR 有"清零"门禁，但 P1/P2 若无归宿就会攒成技术债。本机制让每条问题都有明确归宿，而不是"先记下来后面再说"。

## 铁律

1. **逐条，不抽样**——范围是主问题 + 每条下挂追问，少过一条即本次质检无效。
2. **正确性必须人工金标**：工具只能拦格式与覆盖度；算术与经验数字的**正确性由人复核**。结论里不得出现"已验证正确"，只能说"已重算一致"或"待人工确认"。
3. **先读原文再下判断**，禁止凭卡片标题猜内容。
4. 语义问题（是否预设结论、提示是否泄题、类比是否恰当）永远需要人判，不要假装工具能判。
5. **台账完整性**：门禁只能管「已列出的行」。**漏列**已由 H4 锚点覆盖机械化拦截（行数 < 锚点数即 FAIL）；但**已列出却判错**（如两处同源错误只判了一处）仍需第 6 步人工同源扫描。"没查出来"永远不等于"没问题"。
