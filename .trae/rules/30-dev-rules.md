# 开发工程规则

## 一、源工程与产物（重要）

**已重建源工程**：`dist_course.html` 不再是唯一文件，而是构建产物。

```
src/shell.html               除课程正文外的全部内容（head / style / 骨架 / 侧边栏 / JS）
src/lessons/lesson-<id>.html 每课正文（纯文本 HTML，不含转义）
src/lessons/manifest.json    课程映射表 —— 唯一事实源（2026-10-04 起 **id ≡ display ≡ 学员看到的课号**）
scripts/build.py             组装脚本
tools/content_verify.js      内容层验证（零依赖，随时可跑）
tools/coverage_check.js      覆盖地图归档校验（零依赖；gate 第 3 把锁）
tools/verify.js              渲染层验证（Playwright，需 npm install && npx playwright install chromium）
dist_course.html             产物，禁止手改
```

| 铁律 | 反例 |
|---|---|
| 禁止手改 `dist_course.html` | 直接在产物里改文案，下次构建被覆盖 |
| 课号一律以 `manifest.json` 为准（**id ≡ display ≡ 课号**，2026-10-04 起统一） | 手写 `switchLesson(3)` 却不去核对 manifest |
| 正文不手写 JSON 转义 | 手工给引号加 `\"`，转义错位导致页面崩溃 |
| 命令：`python3 scripts/build.py` / `--check` | 凭记忆说"构建过了" |

## 二、产物约束

| # | 约束 | 原因 |
|---|------|------|
| 1 | 交付物是**单文件自包含 HTML**，双击即用 | 学员拿到一个文件就能学 |
| 2 | 不引入构建步骤、不引入前端框架 | 降低维护成本，改完即可看 |
| 3 | 课程 HTML 注入进 `#lesson-container`，切课走 `switchLesson(n)` | 便于多课切换与内容隔离 |
| 4 | 进度状态一律走 localStorage（`card_checks` / `qna_checks`） | 刷新不丢进度 |
| 5 | 卡片 ID 在整份 HTML 内**全局唯一** | `data-card` / `tab-ai-N` / `qna-list[data-qna=N]` 靠它关联 |
| 6 | **每次真正构建后，产物自动复制到 `~/Downloads/dist_course.html` 并用浏览器自动打开**（`build.py` 内置，`--check` 不复制不打开） | 用户（2026-11-08 要求）要能直接看到效果，不必回项目目录找；写成代码而非口令，避免漏做 |

## 三、卡片 DOM 契约（硬性）

| # | 契约 | 说明 |
|---|------|------|
| C1 | 卡片平级并列 | 所有 `.card` 的 `parentElement` 必须相同 |
| C2 | **禁止卡片嵌套** | 任何 `.card` 的祖先链上不得出现另一个 `.card` |
| C3 | DOM 深度一致 | 所有卡片在 DOM 树中的层数一致 |
| C4 | `div` 配对平衡 | 每张卡片边界内 `<div>` 与 `</div>` 数量相等 |
| C5 | **`.card .footer-nav` 不存在** | 页脚是课程级元素，被吞进卡片即为漏写 `</div>` |
| C6 | 每张 `.card` 必须含 `.tab-bar` | 缺 tab-bar = 丢了 AI 助教与预判追问模块 |
| C7 | 每张 `.card` 必须含 `.card-q-text` / `.card-q-hint` / `.card-a` / `.qna-list` | 四件套缺一即结构不完整 |
| C8 | 新课堂的 QnA 数据禁止用 ASCII `"` 包裹中文 | 会破坏 JS 语法，触发 Console 报错 |

## 四、验证工具链

两层验证，分工明确：**一个管「写得对不对」，一个管「渲染对不对」**。

| 脚本 | 层 | 依赖 | 判什么 |
|:---|:---|:---|:---|
| `tools/review_check.js` | 逐条核验层 | **零依赖**，随时可跑 | ① 报告存在 + 覆盖度（主问题 + 每条追问一条不漏）；② **断言覆盖 H4**：报告里以「Card N」定位的行数 ≥ 该卡**可核验断言数**（2026-09-28 由「结构单元锚点」升级而来；断言判定 = 卡片内容区按块级边界切句后，含数字或归属/时间/版本声明的句子各算 1，步骤标签编号先剥掉，激活区固定 2 条）；③ **类型路由**：9 列契约、类型合法、核验方式与类型匹配、来源满足该类型举证要求，**H1d 事实类判 PASS 必须给一手链接**、**H1e 事实类联网覆盖率**；④ 硬约束 H2/H3：经验类无一手来源不得判 PASS、推导类必须写边界/反例；⑤ **盲审持久化 A1~A3**：`reports/<id>-盲审.md` 必须存在、须含 ≥5 行缺陷表且带联网证据、核验报告须含「差集」段与**显式漏检率数字**——不做盲审即 FAIL；⑥ **问题闭环 B1~B3**：WARN/ERROR 行必须填「处置」（已修/待修/不改），「不改」须带理由，「待修」条数被显式计数；⑦ 置信度/判定枚举合法、ERROR 已清零 |
| `tools/content_verify.js` | 内容层 | **零依赖**，随时可跑 | 7 大组件、div 配平、卡片嵌套、id 绑定一致、追问条数、数字门禁、QnA 数据可解析；**全局**：标题四处一致（manifest / 课内 h2 / `LESSON_TITLES` / 侧边栏，FAIL 级，2026-10-03 新增）；**质量维度（WARN 级）**：非首卡正文首句桥接、正文含生活类比、同卡不出现多个 `d_model` |
| `tools/verify.js` | 渲染层 | Playwright（chromium） | 布局重叠、溢位、对比度、响应式 768px、点击区、Console 错误、交互与切课 |
| `tools/coverage_check.js` | 覆盖地图归档层 | **零依赖**，随时可跑 | ① `docs/coverage-maps.md` 里 manifest **每一课**都有一节（新课漏写 = FAIL）；② 每节四段齐备（标准知识块 / 本课覆盖 / 其余去向 / 有意不讲）；③ **领域锚点落地**：锚点表里每个锚点必须真的出现在该课 `src/lessons/lesson-<id>.html` 正文里；④ **回归护栏**：学生页面不得再出现 `class="coverage-map"` |

命令：

```
node tools/review_check.js --lesson <id>   # 逐条核验覆盖度（生成/质检后必跑）
node tools/content_verify.js          # 查产物
node tools/content_verify.js --src    # 查源（定位更准，推荐先跑）
node tools/verify.js                  # 渲染层，首次需 npm install && npx playwright install chromium
node tools/coverage_check.js           # 覆盖地图归档 / 锚点落地 / 学生页面无残留（gate 第 3 把锁）
python3 scripts/build.py --check      # 产物与源是否一致
python3 scripts/build_site.py         # 生成多页站点 site/（每课独立 URL，SEO + 站内全文搜索；部署到 GitHub Pages 用，gitignore）
python3 scripts/build_site.py --check # site/ 与源是否一致（改了 shell.html 或课程正文后必跑）；语义向量陈旧也会 FAIL
python3 scripts/embed_docs.py         # 课程正文改了之后重算语义向量（只补算变化的行，写 src/search/embeddings.*）；本机要走远程方式，步骤见脚本顶部
```

> **逐条核验**是硬要求：报告缺失或覆盖不全 = 等于没做逐条核验，本次生成/质检不算完成。报告格式与范围见 `.trae/skills/card-review/SKILL.md`。
>
> **脚本的能力边界（必须向使用者说清）**：`review_check.js` 只负责**暴露候选错误**与**不许偷懒**，**不负责证明「对」**。它保证不了的两件事：① 台账是否完整（漏列一条断言 = 门禁看不见，必须靠 `card-review` 第 6 步对抗式复查）；② 每条断言的实质正确性（算术靠复算一致、事实靠一手来源、经验数字只能标「估算」，最终仍需人工金标）。类型路由表见 `card-review` 第 4 步。

渲染层未装依赖时，**必须明确声明「未跑渲染层验证」**，不得默认全绿。

**评分构成**：基础功能 18 项（1pt/项 = 18）+ UI 质量 11 项（82pt）+ DOM 结构 6 项（36pt）。

- 基础功能：HTTP、标题、侧边栏、导航、加载、切换、内容泄漏、Console 错误、进度、localStorage、键盘导航、侧边栏收起、roadmap、meta-tags、footer-nav 等
- UI 质量：布局重叠(10)、导航项对齐(6)、卡片间距(6)、水平溢位(10)、字体层级(6)、footer-nav 对齐(6)、行宽(8)、响应式 768px(10)、可点击区域(8)、留白密度(6)、对比度 WCAG AA(6)
- DOM 结构：父容器一致性(8)、卡片嵌套(8)、DOM 深度一致(5)、渲染后结构未错位(5)、footer 吞入卡片(5)、tab-bar/qna-list 缺失(5)

> **记分口径修正**：历史文档写「满分 126 / DOM 31pt」，但按各检查项实际权重相加是 18 + 82 + 36 = **136**。脚本以实际权重和 136 为准并归一化到 100 分制。改权重只改脚本里的 `weight`，不要维护两套数字。

### 验证触发时机（验证有成本，仅在必要时跑）

| 触发条件 | 动作 |
|----------|------|
| 改了 `src/lessons/*.html` 或 `src/shell.html` | 构建（产物自动复制到 Downloads 并打开）→ `content_verify.js` → `verify.js` → **`embed_docs.py` 重算语义向量 → `build_site.py`** |
| 改了 CSS / 侧边栏 / 交互 JS | 构建（同上自动交付 Downloads 并打开）→ `verify.js` → `build_site.py`（不涉及向量，但需重建站点） |
| 改了 `manifest.json` | `build.py --check` + `content_verify.js` |
| 改了 `tools/*.js` 或 `scripts/build.py` | 跑该脚本自身验证自洽性 |
| **改了 `.trae/rules/**` 或 `.trae/skills/**`** | **跑「规则卫生」5 条清单（第八节）——规则/skill 的增删改一律由读数决定，不靠即兴** |
| 纯讨论、纯 `.md` 变更 | **不跑验证** |
| 不确定变更影响面 | 跑 `content_verify.js`（宁可多跑，不可漏检） |

### 验证铁律

| # | 规则 | 反例 |
|---|------|------|
| 1 | HTML 变更后必须跑 verify ≥90 分才能交付 | 改完说"应该没问题"但没跑 |
| 2 | 新增课程 / 功能时同步更新 verify.js 基础检查项 | 加了第 5 课但 verify 没加切换验证 |
| 3 | 验证失败先分析是代码 bug 还是检测逻辑过时 | 对比度误报直接放宽检查条件 |
| 4 | UI 质量扣分项应修复，不累积技术债 | "97 分差不多了"然后下次又掉分 |

## 五、问题驱动的自动化防御（Bug → Check → Never Again）

> 核心原则：**每次修完一个问题，必须追问"下次怎么自动拦住它？"**

```
问题被发现 → 修复 → 问自己：这个错误下次能自动检测吗？
                    ├─ 能 → 在 verify.js 或 content_verify.js 加检查项
                    └─ 不能 → 至少在本节记录，积累为检查清单
```

**必须触发本工作流的事件**：发现 UI / DOM 结构 bug；发现内容缺失；用户指出"和其他课堂不一致"；用户要求做一项改进；质检脚本报出新类别问题。

### 选择原则

| 原则 | 说明 |
|------|------|
| **选最简实现** | 能用一个 `page.locator()` 检查的，不写复杂脚本 |
| **检查你关心的，不检查过程** | 检查"每张卡片有没有 tab-bar"，不检查"创建时用的模板对不对" |
| **失败要报准位置** | 报"第 3 课 Card5 缺 tab-bar"，不报"有 3 张卡片缺 tab-bar" |
| **不需要自动化的情况** | 纯 CSS 调整、一次性内容修改、无法用 DOM 规则描述的语义问题 |

## 六、新增课程一致性清单

新增一课必须同时具备（缺一不可），且**按 `course-build` skill 的四处同改清单执行**：

1. `src/lessons/lesson-<id>.html` 正文 + `src/lessons/manifest.json` 登记映射
2. 侧边栏 `.nav-item`（`data-lesson` 与 `switchLesson(id)` 对应，id 以 manifest 为准）
3. `.lesson-intro`：标题 + 副标题 + `.roadmap` + `.meta-tags`
4. 每张卡片：`.card-q-text` / `.card-q-hint` / `.card-bg` / `.content-section` / `.calc-block` / `.tab-bar` / `#tab-ai-<id>` / `#tab-qna-<id>` / `.qna-list[data-qna="<id>"]`
5. `LESSON_TITLES` / `LESSON_DISPLAY` / `cardTopics` / `allCardTopics` 登记该课
6. 课间 `.footer-nav` 前后导航链接
7. `content_verify.js` 与 `verify.js` 无需改（按 manifest 与 DOM 自动遍历），但必须跑通
8. **覆盖地图（docs 侧，非交付物）**：`docs/coverage-maps.md` 补该课一节（四段：本领域标准知识块 / 本课覆盖 / 其余去向 / 有意不讲），并在 `tools/coverage_check.js` 的 `ANCHORS` 登记该课锚点 —— 否则 `coverage_check` FAIL → gate BLOCKED
9. **语义向量必须重算（2026-11-08 用户要求，永久生效）**：新增/修改课程正文后，先 `python3 scripts/embed_docs.py` 重算语义向量（只补算变化行），再 `python3 scripts/build_site.py`。**否则语义向量陈旧，`build_site.py --check` FAIL → gate BLOCKED**，站点会静默降级成纯词法搜索（丢失"换个说法/中英互通/错拼"的语义匹配）。**禁止以"词法搜索能用"为由降级部署**——新课必须支持完整的既有搜索功能。

## 八、规则卫生（harness 自进化机制）

> **判据**：这件事**有没有唯一正确答案**？有 → **脚本**（AI 每轮重判既不一致也不省钱）；没有 → **AI 判，且只需信息独立地判一次**，结论落文档。不要问"哪个更聪明"。
> **历史与理由**（为什么上这套机制、已执行过哪些降级）→ `技术分享/05-迭代日志.md`（按需检索，不占常驻）。

### 8.1 双向升降级路径（唯一允许的演进方式）

```
AI 判 → 同一件事反复判出同一结论 → 固化成脚本（把 AI 从重复劳动解放）
脚本 → 出现误报或诱导          → 退回 AI 判 / 直接下线
```

| 方向 | 触发条件 | 动作 |
|---|---|---|
| **升级**（AI → 脚本） | 同一判断**连续 3 轮**结论一致，且判据能写成确定规则 | 固化成脚本，并登记 |
| **降级**（脚本 → 人判） | 该检查**连续报同一条告警却从未被修**，或**产生误报/诱导优化指标** | 下线该检查，改由核验台账「语义」类行承担 |
| **删除** | 脚本里某项**连续 3 课零命中**且无回归价值 | 删除，避免维护成本 |

> **误报的诊断项比没有检查更糟**——它会训练人忽略告警，进而让整套门禁失去可信度。

**已登记的两条操作纪律（2026-10-10，由"29/30 课被静默回退"事件触发）**：
