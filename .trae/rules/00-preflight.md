# IRON-RULE（最高优先级 · 与"逐条核验"相关的一切以此为准）

**逐条核验不可跳过、不可抽样、不可省 token、不可省联网调用。**

## IRON-RULE-0（最高优先级 · 2026-09-29 用户要求 · 永久生效）

> **交付标准 = 0 FAIL 且 0 WARN。** 不是"FAIL 清零即可"，而是**四道门禁的 WARN 也必须清零**。

1. **判定口径**：`gate.js` 报 `GATE = OPEN` **且** 下列四条命令**全部**满足 `FAIL = 0` **且** `WARN = 0`：
   ```
   node tools/gate.js                   # 必须 GATE = OPEN
   node tools/provenance_check.js       # 必须 FAIL 0 / WARN 0
   node tools/review_check.js --all     # 必须 FAIL 0 / WARN 0
   node tools/content_verify.js --src   # 必须 FAIL 0 / WARN 0（内容分 100）
   python3 scripts/build.py --check     # 必须 PASS
   ```
2. **WARN 不是"可接受项"**：任何 WARN 都必须**当轮处置**——要么改内容消除它，要么改检查器消除误报（须附负向自测），**不允许"记录在案、下轮再说"**。
3. **禁止用"降级检查器"来清零**：把 FAIL 改成 WARN、把 WARN 改成 PASS、放宽阈值、加豁免——**只有在该判定确属误报、且能给出反例证明时**才允许，并必须在规则文件里留下"为什么是误报"的记录。
4. **禁止声称完成**：只要任一命令出现 WARN 或 FAIL，**不得**说"已完成 / 已交付 / 已优化"；只能说"未完成，剩余 N 条 WARN"。
5. **每轮收尾必须实跑这五条命令并把读数写进回复的「闸门」段**——读数必须来自真实执行，不得凭记忆填写。

   - **不知道该搜什么时，用这两条兜底模板**：① 「⟨断言⟩ 是否准确或过时」② 「⟨断言⟩ 是否有错误」。
   - 由 `review_check.js` 的 **H1f** 强制：任一行既无 http 又无 `query=` 即 **FAIL**。
   - **禁止"一切都塞给 python"，也禁止"用记忆代替搜索"。**
3. **禁止以任何理由降级执行**：不因"省 token""省联网次数""这轮只是小改动""先做别的回头再补"而跳过。**成本高是既定代价，不是豁免理由。**
4. **机械锁（两道，必须全绿）**：
   ```
   node tools/provenance_check.js       # 台账时效性：内容改过而台账未重核验 → FAIL
   node tools/review_check.js --all     # 逐条覆盖度 / 类型路由 / 盲审 / ERROR 清零
   ```
   任一课 FAIL 未清时：**① 禁止进入下一个任务；② 禁止声称「已完成 / 已优化」**；必须先把该课缺的核验补完，并用 `--stamp` 记录内容指纹。

# 【强制前置检查】每轮对话的第一步

> 下面三步是**每轮对话的开场动作**，与任务大小无关。跳过 = 违规。
>
> **第 0 步（先于本文件其余一切）：本轮开工的第一条命令是 `node tools/gate.js`。**
> - `GATE = BLOCKED`（任一课 FAIL **或 WARN** 未清）→ 本轮**只允许清账**：补逐条核验、补联网证据、修台账、修检查误报、修已判定的 ERROR/WARN。
> - **禁止**：新增课程、改正文、加追问、改结构或 CSS；**也禁止"插入工具建设来替代清账"**（这是最容易骗过自己的一条）。
> - `GATE = OPEN`（**且四道门禁 WARN 全为 0**，见 IRON-RULE-0）才可开工。
> - 判据：不是"我知道应该做"，而是"机器算出来允不允许做"。（2026-09-28 用户要求：规避"明知问题却不干活"；2026-09-29 用户追加：**WARN 也必须为 0**）

## 第 1 步 联网搜索（必做）

- **每轮必搜**，即使判断"没必要"也必须搜一条兜底 query。
- 具体流程（意图提炼 → query 构造 → 执行 → 来源分级 → 采纳判定 → 降级）读
  `.trae/skills/preflight-search/SKILL.md`
- 先提炼**本轮核心目的**，用目的而不是用户原话去构造 query；中英文各至少一条。
- 工具层面失败时，明示「本轮搜索失败，以下基于预训练知识，需人工核实」，**不得静默跳过**。

## 第 3 步 输出契约（每轮回复**开头**必须附，2026-09-28 由"末尾"改为"开头"）

> 位置规定：`[联网自检]` + `[来源]` 一律放在**回复的最上面**，正文之后不再重复。
> 理由（用户 2026-09-28 明确要求）：读者先看到"这轮搜了什么、采信了什么"，再读结论——来源成为结论的前置条件，而不是读到最后才补的附录。

```
---
[联网自检] 已联网：是｜N 轮｜采纳：S1（一句话概括支撑了什么）｜新增/变更：无
[来源] S1 A级 https://… ｜ S2 B级 https://…
```

- **默认只给一行摘要 + 一行来源**（2026-09-28 用户明确要求：不需要大表格明细，"你自己看就行"）。
- 展开明细**仅在**下列情形需要：① 用户明确要求；② 检索出现**来源冲突**或与卡片结论**实质不符**（此时必须点名列出双方来源与差异）。
- 自检字段**必须诚实**：没搜就写"否 + 原因"，不许为合规谎报。
- 来源等级：A 论文/官方文档 ｜ B 官方博客/知名团队 ｜ C 技术博客 ｜ D 论坛问答。
- **重要**：摘要只是"输出格式"简化——**台账里的逐条 URL/query 证据一个都不能少**（由 `review_check.js` H1f 强制）。

### 输出骨架（固定 5 段 · 顺序不可变 · 2026-09-28 用户要求）

> 问题背景：此前每轮结构不一，读者找不到"结论 / 方法 / 要确认什么"。以下为唯一允许的骨架。

```
[联网自检] 一行摘要
[来源] 一行来源

## 结论            ← 1–3 句，直接回答"做完了没 / 发现了什么 / 卡在哪"。禁止铺垫。
## 证据            ← 读数 / 文件链接 / 紧凑表格。只放能支撑结论的，不贴过程。
## 方法            ← 只在"改了东西"时写：改了什么、为什么这样改（≤5 行）。
## 需要你决策       ← **只写一件事**；无则明写"无"。禁止流水账、禁止列 5 条。
## 闸门            ← `GATE=BLOCKED/OPEN` + 剩余 FAIL 数 + 下一轮唯一动作（1 条）
```

**硬规则**：
1. **一级标题只允许上面这 5 个 + 顶部自检块**；不得再自创章节名或混用层级。
2. 「需要你决策」**最多 1 条**；若确实无待决策项，写"无"，不要凑。
3. 「闸门」段的"下一轮唯一动作"**必须只有 1 条**——多任务时按闸门优先级取最高的一条，其余不写。
4. 结论段禁止出现"部分完成""基本可用"这类模糊词：要么给数字，要么写"未完成"。
5. 长清单（>5 行）一律移入文件（`reports/` / `docs/`）并在证据段给链接，不铺在回复里。
