② 说清为什么生成任务必须用 Causal Mask，以及它怎么把 BERT 和 GPT 分成两条路
③ 向别人解释「RNN 到底哪里不行」并用具体数字举例，而不是背概念
🗺 本节推理链（6 步：任务约束 → RNN 撞墙逼出 Self-Attention → Causal Mask → Softmax 加权 → Multi-Head → KV Cache，即生成时把已算过的键和值存下来复用、不必每步重算）
1 任务约束：跨任意距离传信息，且能并行 — 语言建模要求每个位置能直接读到前面任意远的 token（长距离依赖），又不能按时间步串行。用「我把昨天在图书馆借的那本书还了」试：句首的"把"和句尾的"还"相隔 12 个字，信息必须跨过这 12 个位置传过来。
↓
2 先试 RNN → 撞墙，逼出 Self-Attention — RNN 用一张被反复覆盖的 hidden state 记笔记，读得越远开头的"把"越模糊，而且只能按时间步串行，两条约束都破。于是让每个位置各自投影出 query / key，点积一次得到 n×n 的分数矩阵，任意两位置直连、可并行。
↓
3 Causal Mask：生成时只能看左边 — 自回归于是只允许看左侧，因此对分数矩阵上三角填 -∞，得到的可见范围只含左下角
↓
4 Softmax + 加权求和：把分数变成输出 — 对保留下来的可见范围因此要做归一化（不用 argmax：不可导），再对 value 加权求和，得到attention 权重；÷√d_k 防 softmax 饱和
↓
5 Multi-Head：一个头不够用 — 上一张卡片的输出只有一组 attention 权重，表达不了"苹果-甜"（属性）与"苹果-买"（动作）等多种关系，于是并行开 h 个 head、各自独立投影，每头一组 每个 head 一组 K/V
↓
6 KV Cache：生成时别重算 — 每个 head 一组 K/V，所以在解码时都要复用；KV Cache 大小 = 2 × 层数 × head 数 × d_k × 序列长

RNN 为什么记不住远处的词？
提示：数一数句首的"把"和句尾的"还"隔了多少个字
▾
知识背景
RNN（Recurrent Neural Network）的标准形态由 Elman 于 1990 年提出，称为 Simple Recurrent Network（更早的循环结构可追溯到 Jordan 1986）；LSTM（Long Short-Term Memory）由 Hochreiter & Schmidhuber 于 1997 年提出，用门控机制缓解了短期记忆问题，但串行瓶颈仍在。2017 年之前，RNN/LSTM 是 NLP 的默认架构，广泛用于机器翻译、语音识别。

先看一个任务：语言建模（language modeling）——给定前文预测下一个 token。用「我把昨天在图书馆借的那本书还了」走一遍：句首的"把"和句尾的"还"构成同一个"把…还了"结构，两者相隔 12 个字（"把"在第 2 位、"还"在第 14 位）——信息必须跨过这 12 个位置传过来。① 相隔任意远的两个位置必须能直接交换信息，即建模长距离依赖；② 不能按时间步串行计算，必须可并行。这两条就是我们要满足的任务约束。

先用 RNN（循环神经网络）撞一下墙。它的工作方式：从左到右，一个词接一个词地读。"我" → 更新隐藏状态 → "把" → 更新隐藏状态 → ...（隐藏状态 = RNN 用来记住"前面所有词"的那个向量。）RNN 的隐藏状态每步都被整体重写（像只用一张便签纸记笔记），读到句尾开头的信息早被擦没了；而且它必须按时间步一个个算。这两点正好同时踩中上面两条约束。在 2017 年之前，处理句子的主力就是 RNN 及其门控版本 LSTM。

打个比方：RNN 读句子像一个人只用一张便签纸做笔记——每读一个词就把便签擦掉重写，便签上只剩当前这一行；读到句尾，开头记的细节早被擦没了。后面所有"遗忘"和"消失"的毛病，都源于这一张便签。

RNN 的三个致命问题：

① 串行慢。第 100 个词必须等前 99 个词全算完。GPU 有几千个核心，RNN 的时间步却只能一个一个来——并行度用不上。

② 远距离遗忘。句子开头的信息传到句尾已经模糊不清。

③ 梯度消失。反向传播（把误差从输出端往回传、据此调参数的算法）沿时间步往回传，每传一步就把梯度乘一个小于 1 的数，传到开头几乎为零。

🧮 具体感受一下"梯度消失"
Step 1：设每步梯度乘 0.9，看 1 / 10 / 50 步后的残余
步数梯度残余含义
10.9还行
100.9¹⁰ = 0.35不到一半了
500.9⁵⁰ = 0.005几乎为零，模型学不到任何东西
Step 2：50 步后只剩 0.005，等于断了
这就是为什么 RNN 处理长句子时，开头的信息根本学不到——梯度在路上"饿死了"。

要让相隔 12 个位置的两处直接比对，该怎么算？
提示：要一次算出所有位置对
▾
知识背景
Self-Attention 出自 "Attention Is All You Need"（Vaswani et al., Google, 2017）。"Self" 的含义是每个词关注同一句子中的所有词（而非跨句关注）。Q/K/V 的术语源于信息检索：Query（你在搜什么）、Key（索引）、Value（实际内容）。今天所有主流 LLM 都基于 Self-Attention。

上一张卡片看到 RNN 的 hidden state 每读一个词就被整体覆盖一次，开头的信息留不住。要解决它，最直接的做法是让每两个位置之间都算一个"像不像"的分数——n 个 token 就是 n×n 张分数表。

Self-Attention 的核心：让每个词都去"查"一遍所有其他词，看它们和自己有多相关。

用图书馆打个比方：Q 是你手里的索书号，K 是每本书书脊上的分类标签，V 是书页里的正文——拿 Q 去和每一张 K 比对，谁最像就把谁的 V 借走。句子里的每个词同时扮演这三种角色。

Q（Query） = "我在找什么？"  K（Key） = "我有什么可以提供？"  V（Value） = "如果选了我，我给你什么信息？"

为什么不直接用词向量本身两两算点积、非要投影出 Q、K？因为词向量的相似度是固定的——不管任务是翻译还是问答，「苹果」和「甜」的分数都一样，模型没法按任务调；投影成 Q、K 之后，同一对词的分数可以被训练成任意大小（本例 Q_我·K_吃 = 0.16 就是这样算出来的）。

🧮 完整计算走查：句子 = ["我", "吃"]，维度简化为 3（Q/K/V 再经 W 矩阵投影为 2 维；以下数值为演示用示意值）
Step 1：输入 Embedding
词d₁d₂d₃
"我"0.50.30.8
"吃"0.20.90.4

"我"看清楚自己：Q_我·K_我 = 0.6×0.4 + 0.2×0.7 = 0.24+0.14 = 0.38
"我"看清楚"吃"：Q_我·K_吃 = 0.6×0.1 + 0.2×0.5 = 0.06+0.10 = 0.16

关键洞察：所有词的计算是同时进行的——这就是为什么 Self-Attention 能并行，比 RNN 快得多（尽管总计算量更大）。

🎯 Q、K、V 的本质角色

Q（Query） = 每个词在问"谁和我最相关？"
K（Key） = 每个词在答"我是什么，来找我"
V（Value） = "如果真的选了我，我给你这些信息"

这种"查询-索引-取值"的三步机制，让 Self-Attention 的每条信息路径长度恒为 1——不管两个词距离多远，梯度都能一步直达。这就是它在"长距离依赖"上明显优于 RNN 的核心原因。

生成时不允许看后面的词，这个限制加在哪一层最自然？
提示：限制的对象是刚算出的那张分数矩阵
▾
知识背景
Causal Mask 中的 "Causal" 指因果——原因必须在前、结果必须在后。GPT（Radford et al., OpenAI, 2018）把「因果掩码 + Decoder-only」确立为生成式预训练范式（规模化验证由后续 GPT-2/GPT-3 完成；因果掩码本身在 2017 年原论文的 Decoder 里就已使用）。这一机制让模型不能"偷看"未来的词——是 Decoder-only 架构（GPT）和 Encoder-only 架构（BERT）分道扬镳的关键。

上一张卡片算出了一张 n×n 的分数矩阵（attention 分数）。但生成有个前提：模型从左往右吐词，生成"我"的时候"爱"还不存在。所以矩阵里"列号大于行号"的格子（上三角）必须作废——填成 -∞，Softmax 之后自然是 0。

这就像闭卷考试：练习时若允许翻书（看到未来），上考场却只能凭记忆，成绩必然崩，所以练习就得按考场规则来。

训练一个"理解"任务时，双向注意力没问题——"苹果很甜"中，"甜"确认了"苹果"是水果。

但生成时完全不同。模型从左往右逐 token 生成，生成"我"的时候，"爱"还不存在。如果在训练时允许模型"偷看"未来 token，那它上线做生成任务时会彻底蒙圈——因为真实世界里未来 token 就是不可用的。

🧮 Causal Mask 怎么加的？
句子 = ["我", "爱", "你"]，正常 Q×K^T 矩阵（构造的示意值）：
"我""爱""你"
"我"0.50.30.1
"爱"0.20.60.4
"你"0.10.30.7
"我"能看到"爱"(0.3)和"你"(0.1)——训练时偷看了未来！
加上 Causal Mask（上三角 = "列号大于行号"的那些格子 → -∞）：
"我""爱""你"
"我"0.5-∞-∞
"爱"0.20.6-∞
"你"0.10.30.7
Softmax 之后（e^(-∞) = 0，其余正常归一化）：
"我""爱""你"
"我"1.000
"爱"0.400.600
"你"0.250.300.45
✅ "我"只能看到自己，"爱"能看到"我"和自己，"你"能看到前面所有。因果链成立。
🎯 这个限制带来的分岔

同一个架构，只因"要不要挡未来"，就分成两条路。BERT 不挡（双向 Encoder，做理解），GPT 必须挡（单向 Decoder，做生成）。

BERT（不挡未来）GPT（必须挡）
能看到左右两边只有左边
擅长理解（完形填空）生成（续写）
训练目标MLM：遮住 15% 的词去猜自回归：预测下一个词
🎯 -∞ 与 0 的差别：Softmax 之后各是什么

填 0 → Softmax 后 = e⁰/(...) ≠ 0，被 mask 的词仍有残留权重。

填 -∞ → Softmax 后 = e^(-∞)/(...) = 0/(...) = 0，真正"完全忽略"。

分数矩阵要变成"把信息搬过来"的动作，先得做哪一步归一化、不做会怎样？
提示：分数是"像不像"，不是"内容"
▾
知识背景
BERT = Bidirectional Encoder Representations from Transformers（Devlin et al., Google, 2018）——双向 Encoder，MLM 训练，擅长理解任务。GPT = Generative Pre-trained Transformer（Radford et al., OpenAI, 2018）——单向 Decoder，自回归训练，擅长生成任务。源于同一篇 Transformer 论文（2017），走向了两条路线。GPT 系列统治对话 AI，BERT 系列（RoBERTa/DeBERTa）统治 NLU 基准。

上一张卡片用 mask 把分数矩阵的可见范围限成了左下三角。但这些数字只表示"像不像"——要真的把内容搬过来，还需要 V，并按分数做加权求和。

加权之前必须先归一化：每一行除以自己那行的总和，让权重加起来是 1。这里只能选 softmax——argmax 虽然也能"选一个"，但它不可导，梯度传不回去。

打个比方：分数矩阵像一张"兴趣打分表"，不能直接拿去分配信息——两个人合伙出资，不能按出资的绝对金额直接分账，得先按比例折成各自的份额；这个"把打分折成占比"的动作，在数学上就是 softmax 归一化。

而一旦用了 softmax，新的麻烦就来了——这也是 ÷√d_k 存在的原因。

Encoder-only（BERT）Decoder-only（GPT）
注意力双向（看全部）单向（←只看左边）

🎯 不除 √d_k 会怎样

以原论文 base 的每头维度 d_k=64（d_model=512、8 个头）为例，两个独立随机向量点积的标准差约 √d_k=√64=8（期望为 0）；每头维度越大，点积方差越大。不缩放的话，Softmax 输入量级太大 → 输出极度尖锐（≈one-hot）→ 梯度趋于零，模型学不动。

除以 √d_k 把量级拉回 1 附近。这就是一根"保险丝"——d_k 小时无害（本卡走查的小例子里 d_k=2），统一保留。

多开几个注意力头，究竟比单头多看到了什么？
提示：挑一个词，看它同时和哪几个词发生关系
▾
知识背景
Multi-Head Attention 同样出自 "Attention Is All You Need"（2017）。原论文设 h=8 个头，每头 d_k=64。与 CNN 的多卷积核同源：不同头捕捉不同关系模式。现代 LLM 的头数随规模变：Llama 2 7B 是 32 头（隐藏维度 4096、每头 128 维），Qwen2.5-7B 是 28 头（隐藏维度 3584、每头仍是 128 维），Llama 2 70B 是 64 头。

上一张卡片只算了一组 attention 权重——所有关系被迫压进同一张矩阵。但"苹果"和"甜"（属性）、"苹果"和"买"（动作）、"苹果"和"斤"（数量）是三种异质关系，一组权重表达不了。

就像多个人同时读同一句话：一个人盯语法、一个人盯语义、一个人盯数量，最后把各自的笔记合并成一份更完整的理解。

"苹果很甜，我昨天买了三斤"——"苹果"既和"甜"有关（属性），又和"买"有关（动作），还和"斤"有关（数量）。一个头很难同时捕捉三种异质关系。

那能不能干脆不分组，只把单头加宽（每头维度由 64 提到 128）？不能——加宽只是把同一张打分表放大，Softmax 之后仍然只有一行权重；要同时表达「属性 / 动作 / 数量」三套彼此独立的分布，就必须真的开出三个头，让它们各持一张打分表。

🧮 Multi-Head 的计算本质
Step 1：按原论文口径，d_model=512、h=8 个头
每头分到 512/8 = 64 维（与知识背景里的 d_k=64 一致）
Step 2：每头独立算，再拼回 512 维
每头独立算 Attention（64 维的 Q、K、V）
8 个头各自输出 64 维 → 拼接回 64×8 = 512 维
最后过一个线性层 W_O，把拼接结果再融合一次
总计算量和单头一样（每头维度缩小了），但能学到 8 种不同的"注意力模式"。

头#1 把 55% 注意力给"甜"，头#3 把 62% 给"买"，头#6 把 72% 给"斤"——每种关系都有专属的"专家"。单头永远做不到这种专业化。
🎯 为什么 GQA（把多个 Query 头分成几组、每组共享同一份 K/V）能把 KV Cache 降到 1/g 而不掉点

因为很多头是冗余的——Voita 等人 2019 年的分析显示注意力头存在大量冗余：在他们的英俄翻译模型里，48 个头剪掉 38 个，BLEU 只掉 0.15。GQA（Grouped Query Attention）正是基于这个洞察。它让多个 Q 头共享一组 K/V，从而大幅压缩 KV Cache、同时几乎不掉点——这里的 KV Cache，指生成时把已算过的 Key/Value 存下来复用、避免重复计算。

这也是为什么从 Llama 2 70B 开始、到 Llama 3 全系列，以及 Mistral、Qwen 都用 GQA 而非纯 MHA（Multi-Head Attention，标准多头注意力；Llama 2 的 7B/13B 仍是 MHA）——不是越多头越好，是聪明的分组更好。

解码时什么被重复计算了？
提示：看每一步都要用到前面哪些 token 的什么
▾
知识背景
自回归（Autoregressive）含义：用过去值预测未来值。在语言模型中：P(w_t | w_1...w_{t-1})。从 n-gram（1950s）→ 神经语言模型（Bengio et al., 2003）→ GPT（2018）。所有 Decoder-only LLM（GPT、Llama、Claude、Gemini）都基于自回归生成——上一步输出成为下一步输入。

上一张卡片的多头结构意味着：每个 head 一组 K/V 都要各自算一份。进入生成阶段后，每一步都要用到前面所有 token 的 K/V——不缓存就得反复重算。

🧮 完整走一遍：GPT 生成 "我爱吃苹果"
初始：输入 = [BOS]
BOS = Begin of Sequence（开始符，告诉模型"从这儿开始生成"）；配套的 EOS = End of Sequence（结束符，模型输出它就表示"这句话说完了"）
第1步：输入=[BOS] → 预测（以下概率为示意值）
候选：我(0.32), 今天(0.18), 请(0.09)... → 采样选中"我"
第2步：输入=[BOS,"我"] → 预测
候选：爱(0.41), 想(0.22), 喜欢(0.15)... → 选中"爱"
第3步：输入=[BOS,"我","爱"] → 选中"吃"
第4步：输入=[BOS,"我","爱","吃"] → 选中"苹果"
第5步：输入=[BOS,"我","爱","吃","苹果"] → 预测到 EOS → 停止
✅ 输出："我爱吃苹果"
步数当前输入预测概率计算量 (不含Cache)
1[BOS]我0.321×d
2[BOS,我]爱0.412×d
3[BOS,我,爱]吃—3×d
4[BOS,我,爱,吃]苹果—4×d
5[BOS,…,苹果]EOS—5×d
无 KV Cache 时总计算量 = (1+2+3+4+5)×d = 15d。有 KV Cache 后 = 5d（只算新 token）。Cache 省了 67% 计算。（该比例随序列变长而升高：100 步时约 98%，见本卡追问 5）

关键洞察：每一步输入越来越长，但有了 KV Cache（后面课时讲）——它就像一张草稿纸。前面 token 算过的 Key、Value 直接抄在纸上，下一步不用重算，只算新 token 的。

这就是 Causal Mask 必须存在的原因——每一步生成时，模型只能看到"已经出生"的 token，未来的还没出生。

BERT 做 Embedding = encode 一次，拿向量就用。GPT = 逐 token 生成。

但 GPT 也能做 Embedding——最朴素的做法是取最后一个 token 的 hidden state 作为整个序列的表示；而真正把 Decoder-only 改造成 Embedding 模型的 LLM2Vec、GTE-Qwen、NV-Embed 都各自做了额外改造（LLM2Vec 加双向注意力改造 + 池化，GTE-Qwen 走指令微调，NV-Embed 用 latent 池化——都不是单纯"取最后一个 token"）。（注意区分：E5 原始版基于 BERT 式双向编码器，BGE 基于 BERT 编码器 + CLS 池化，都不是 Decoder-only 取 last-token 的做法。）Decoder-only 正在"侵蚀"原本属于 BERT 的领地。
